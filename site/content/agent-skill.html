Install actually-done as a skill

Let an agent invoke the CLI and explain its evidence. Install the executable separately.

Copy the complete skill folder

From the source checkout, copy skills/actually-done, including its license and metadata, to the chosen destination. Review existing installations before replacing them.

Start a new agent session in the target project after installation. A cloud agent needs its own local process access, CLI, repository, and supported transcript; copying a skill does not grant access to your computer.

Give the agent a concrete task

$actually-done Check the completed Codex session at /path/to/rollout.jsonl
against this repository. Run cargo test --locked; this command is authorized.
Report the exact verdict, fresh test status, findings, and uncertainty.

For Claude, use /actually-done and a Claude transcript path. Use your project’s test command or state an explicit waiver. Existing task authorization counts.

Optional installer

With Node.js and network access, run this from the target project:

npx skills add M-Umer-Farooq-Dev/actually-done --skill actually-done --agent codex claude-code --copy

This third-party command was verified in an isolated project. It installs the skill, not the executable. The installer has its own policies; manual copying remains available.

The skill preserves the evidence boundary

It checks session selection, uses JSON plus exit status, distinguishes agent-reported tests from fresh tests, and explains live-session limitations. Transcript text and test output are untrusted data. The skill does not introduce a repair loop or merge on the basis of a verdict.

Read the full LLM guide with Bash and PowerShell installation and the actual skill instructions.

The CLI never uploads transcripts, but an agent reading its receipt may send content to its model provider. Review sensitive excerpts before sharing.
