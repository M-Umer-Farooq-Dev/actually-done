Codex guide

Check a Codex session against Git and fresh tests

Select a completed rollout and get a receipt that keeps completion claims, fresh evidence, and uncertainty together.

Select a rollout

Discovery searches ~/.codex/sessions and ~/.codex/archived_sessions. It uses resolved working-directory metadata. Subagent transcripts are excluded and their presence is noted.

actually-done . --provider codex --session /path/to/rollout.jsonl --test "cargo test --locked" --json

Replace the paths and command with the actual project inputs. You can also select a known session ID. Prompt index defaults to zero; specify --prompt-index for another prompt.

Read JSON and exit status together

Capture stdout, stderr, and process exit separately. For exits 0 and 1, parse stdout as JSON schema "1". Check provider, session_path, prompt, verdict, tests, leftovers, uncertainty, and parse_warnings. Exit 2 may have only a stderr diagnostic; exit 130 means interruption without a verdict.

Check the handoff, then review implementation quality

The receipt uses deterministic language heuristics and current Git evidence. It does not attribute changes to the session, inspect changed file contents, or prove deployment readiness. Failed write attempts are distinct from observed successful writes; duplicate events and cumulative token reports are handled without counting the same evidence twice.

The Codex skill packages this workflow. Keep verdict limitations in any summary you share. See official Codex skill documentation for discovery paths.
