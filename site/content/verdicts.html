Evidence reference

What does the completion verdict mean?

DONE means “no gaps detected by the available checks.” Every receipt still has limits.

Does DONE prove the code is correct?

No. The receipt checks claims and available evidence using deterministic heuristics. It does not prove correctness, security, deployment, or authorship. Passing tests only cover their actual assertions.

Can passing tests still produce PARTIAL?

Yes. An unresolved obligation, file mismatch, or heuristic scope concern prevents DONE. Reproduce a passing-test example with unfinished work.

What if a claimed file is already committed?

It may be flagged as “not seen in current changes.” Git evidence covers current status, not session history. Existing changes can also predate the session. Read the uncertainty before interpreting a mismatch.

What happens without a test command?

Configuration can supply one. Precedence is CLI, repository .actually-done.toml, global ~/.config/actually-done/config.toml, then defaults. If none is configured and tests are not waived, they are unverified. Tests are guessed only with explicit --guess-test or configured guess_test = true. --no-test overrides test sources.

Does it upload transcripts?

The CLI never uploads them and has no telemetry or API calls. Recognized credential patterns are redacted, but redaction is incomplete. Receipts can contain private prompts, paths, and test output. An agent that reads a receipt may send its content to its configured model provider.

Can I check the session currently running?

You can collect evidence, but no final completion claim may exist yet, or a new user request may make an earlier response ineligible. Prefer an existing completed transcript. Never edit a transcript to influence the result.

Does it replace code review or CI?

No. Use it to find handoff gaps, then review implementation quality and run integration or release checks. It does not inspect changed file contents or repair findings.

What should automation do with exit 1?

Parse the receipt: PARTIAL, NOT DONE, and UNKNOWN all use exit 1. For --json, require schema "1" and matching process/receipt exit codes. Treat invalid JSON or unexpected schemas as integration errors, not completion.
