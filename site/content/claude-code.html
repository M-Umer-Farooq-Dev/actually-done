Claude Code guide

How to verify that Claude Code completed a task

Check the completion claim against current changes, a fresh test run, and unfinished work in the transcript.

1. Select the project and completed session

Run from the project’s Git repository. Automatic discovery searches ~/.claude/projects and matches transcript working-directory metadata. An explicit transcript makes the assessment easier to reproduce.

actually-done . --provider claude --session /path/to/session.jsonl --test "pytest -q"

Replace the path and test command. Use --prompt-index N to select another user prompt; the default is zero. Check the selected prompt and session in the receipt.

2. Use fresh evidence

Tests reported by the agent are recorded separately from tests actually run by this command. The default timeout is 120 seconds; use --test-timeout to change it. An explicit --no-test waiver is visible.

3. Review the concerns

A file claim absent from current Git changes can produce PARTIAL. It means “not seen in current changes,” not “never changed.” Completed work can already be committed. An unresolved obligation or heuristic scope concern also prevents DONE, even when tests pass.

4. Keep the limitation in the handoff

A currently running session may not yet have a final completion message. Starting a new review prompt in the same session can also affect which claim is eligible. Prefer reviewing a completed session from a separate review session; never add a fake completion event.
