# actually-done Rust variant — 2026-10-01

This is a historical report for the pre-extraction executable `actually-done-rs`. Its checksum and test counts describe that build, not the renamed standalone binary. The native Rust CLI preserves schema 1 receipts and the Python verdict rules. It reduces startup and transcript-processing time. Git and the chosen test suite still contribute their own execution costs.

## Measured performance

Windows x64, AMD Ryzen 9 5900HS (8 cores / 16 logical processors). Python 3.11.6, Rust 1.97.0, optimized release build. Each median uses 7 alternating runs after three warmups per implementation. The filesystem cache was warm. Both processes captured stdout and stderr. The Python command was `python -m actually_done` with the source package on PYTHONPATH.

Decoded JSON receipts and exit codes were compared before timing each receipt scenario. All transcripts were synthetic. Test commands were explicitly waived; these timings do not include running a project's tests. Build and dependency-download times are excluded.

| Scenario | Python median | Rust median | Speedup |
|---|---:|---:|---:|
| startup --version | 178.6 ms | 7.1 ms | 25.02× |
| claude 20 events, git disabled | 177.6 ms | 13.9 ms | 12.80× |
| claude 20 events, git enabled | 391.8 ms | 311.9 ms | 1.26× |

## Verification

- 79 original Python tests pass.
- 9 native Rust contract tests pass.
- 65 differential and safety checks pass against the installed release executable, with warnings treated as errors and no skipped tests.
- Cargo fmt and Clippy with warnings denied pass; Ruff and strict mypy pass for the Python source, parity suite, and benchmark script.
- Cargo install into an isolated directory succeeds; console version and receipt behavior were verified there.

Coverage includes both providers, completion negation, fenced code, checkbox resolution, leftovers, successful versus failed writes, duplicate calls, token totals, stale completion, configuration precedence, archived sessions, nested repos, excluded subagents, Windows junction boundaries, staged/unstaged/renamed and Unicode paths, test failures, timeout descendant cleanup, interruption exit 130, Markdown output, and transcript aliases created before or during tests.

The oversized-file boundary is covered by a native metadata-size contract without allocating a 50 MiB fixture. Runtime verification is Windows x64 only. Other platforms and future vendor formats need further coverage. Human layouts and JSON whitespace/key order/Unicode escaping can differ; decoded JSON is the compatibility contract exercised here.

## Historical reproduction in the original combined checkout

The following commands refer to the original combined Python/Rust development checkout at commit `03fef16`, not this standalone repository. The benchmark harness and Python baseline are not bundled here.

```powershell
cargo build --release --locked --manifest-path rust/Cargo.toml
.\rust\target\release\actually-done-rs.exe . --no-test --json
# Or request fresh tests:
.\rust\target\release\actually-done-rs.exe . --test "pytest -q"
cargo test --locked --manifest-path rust/Cargo.toml
cargo fmt --manifest-path rust/Cargo.toml -- --check
cargo clippy --locked --manifest-path rust/Cargo.toml --all-targets -- -D warnings
cargo build --locked --manifest-path rust/Cargo.toml
python -m pytest verification/test_rust_parity.py -q -W error
python benchmarks/compare.py --runs 7 --out benchmark.json
```

A session must match the repository or be selected explicitly with `--session PATH` or `--session ID`. `--no-test` is an explicit waiver. `DONE` means **no gaps detected by the available checks**, with heuristic and current-git limitations visible in the receipt. The CLI never uploads transcripts. Project test commands can have side effects.
