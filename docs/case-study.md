# Passing tests with unfinished work

This synthetic handoff says: “Done. Updated `auth.py`. We should rotate the key later.” There is no production credential. The fixture project contains an untracked auth.py and a small assertion that checks its demonstration behavior.

From this checkout, with Python 3.11+ and the CLI installed:

```console
python scripts/demo.py --binary actually-done
```

The script creates an isolated temporary Git repository and transcript, runs a fresh test command through the CLI, and asserts:

| Evidence | Observed result |
| --- | --- |
| Claimed auth.py | Seen in current untracked changes |
| Fresh test | Passed |
| Key-rotation obligation | Preserved |
| Verdict / exit | PARTIAL / 1 |

The [captured field summary](../site/assets/demo-summary.json) was generated by the script from the actual receipt. It is not a mock terminal screenshot or a security test. The script removes its temporary files and never reads real sessions. Paths and timing vary by machine.

The receipt helps the reviewer find the outstanding obligation before moving on. It does not establish correctness, authorship, or production readiness. Tests cover only their assertions; current Git changes can predate a session, and already committed work can be absent. The [complete demo](../scripts/demo.py), [verdict rules](../README.md#understand-the-verdict), and [agent guide](agents.md) preserve those limits.
